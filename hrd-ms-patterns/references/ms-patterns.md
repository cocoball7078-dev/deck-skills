# MS 특화 장표 패턴 라이브러리 — Microsoft 365 / Copilot 도입·변화관리

목적: Microsoft 365 Copilot 도입·변화관리 제안 덱에서 반복 등장하는 장표 11종의 도식 구조·문구 규칙을 고정해, 매번 새로 설계하지 않고 패턴을 골라 고객 상황에 맞게 채우게 한다.
사용법: ① 제안 흐름(진단→설계→파일럿→확산→고도화)에서 필요한 패턴을 고른다 → ② 「도식 구조」대로 native-deck 도형(셰브론·박스·표·화살표)을 배치한다 → ③ 액션 타이틀 예시는 고객 상황에 맞게 다시 쓰고, 수치는 「수치 표기법」과 「주의점」을 지킨다.
공통 원칙: Microsoft 공식 프레임워크·제품명을 우선 사용한다. 단계명·제품명은 임의로 바꾸지 않고, 효과 수치는 출처와 측정 전제를 반드시 병기한다.

---

## 패턴 1. Copilot 도입 로드맵 (Copilot Adoption Roadmap)

- **쓰는 상황**: 제안서 본편의 중심 1장. 전체 단계·기간·산출물을 고객 경영진에게 한 장으로 합의받을 때. 후속 장표(파일럿·교육·측정) 전체의 목차 역할도 겸한다.
- **도식 구조**: 가로 셰브론 4개(chevron, 균등 폭)를 상단에 배치하고 공식 단계명을 그대로 넣는다 — ① Get Ready ② Onboard & Engage ③ Deliver Impact ④ Extend & Optimize. 셰브론 아래 4열을 맞추고, 열마다 활동 박스 3개(핵심 활동)를 세로로 쌓는다. 그 아래 한 행은 산출물 행으로 분리해 옅은 회색 박스로 통일한다. 최하단에 전 단계를 관통하는 가로 띠 박스(공통 기반: 커뮤니케이션·챔피언 네트워크·성과측정)를 둔다. 기간 표기는 셰브론 위 작은 텍스트(M1–M2 같은 상대 표기)로만 붙인다.
- **장표 구성**: 액션 타이틀 예시 — "공식 4단계로 나눠 도입하면 리스크는 파일럿 안에 가두고, 성과는 전사 확산 전에 검증할 수 있다". 본문 요소: 단계명(공식 영문 + 한글 풀이), 핵심 활동, 산출물, 다음 단계 전환 조건(Gate). 수치 표기법: 기간은 월 단위 상대 표기(M1~) 또는 주차로만 쓰고 '예시' 병기.
- **주의점**: Get Ready 등 공식 단계명을 자체 용어로 교체하지 않는다(고객 내부 명칭이 다르면 하단에 대응표 각주). 고객 일정이 미확정인데 확정 일정처럼 날짜를 박지 않는다. 단계별 활동은 Microsoft Copilot Success Kit의 단계 구성과 어긋나지 않게 쓴다.

## 패턴 2. 파일럿 설계 (Pilot Design & Scale-up Gate)

- **쓰는 상황**: 도입 범위를 두고 고객이 불안해하거나, 전사 계약 전에 검증 단계를 제안해야 할 때. 제안서의 리스크 관리 근거 장표.
- **도식 구조**: 3단 가로 흐름. 왼쪽 박스 묶음 「대상 선정」 — 대상 부서·인원·선정 기준 3개 체크 항목. 가운데 타임라인 화살표 위에 준비→실행→평가 3개 노드, 노드 아래 각각 활동 박스. 오른쪽 표 박스 「성공 기준·확산 게이트」 — 지표/목표/판정 3열 표. 하단에 확산 경로 미니 셰브론(파일럿 → 부서 확산 → 전사)을 얇게 깔아 파일럿이 끝이 아님을 보인다.
- **장표 구성**: 액션 타이틀 예시 — "파일럿은 '써보는 기간'이 아니라 확산 여부를 수치로 결정하는 검증 구간으로 설계한다". 본문 요소: 선정 기준(업무 대표성, 데이터 준비도, 부서장 협조), 기간, 교육·지원 범위, 성공 기준 표, 게이트 판정 절차(누가·언제·무엇으로 결정하는지). 수치 표기법: 성공 기준은 주간 활성 사용률·시나리오별 과제 소요시간처럼 측정 가능한 지표로 쓰되 목표값은 '고객 협의 후 확정'으로 표기한다.
- **주의점**: 성공 기준 없는 파일럿을 제안하지 않는다('만족도 조사 실시'만으로 게이트를 만들지 않는다). 파일럿 성공을 전제로 전사 물량을 이미 확정한 듯한 문구("파일럿 후 전사 3,000명 확대 예정")를 쓰지 않는다. 대상 선정에서 IT·보안 부서 검증 항목(권한·데이터 점검)을 빠뜨리지 않는다.

## 패턴 3. 부서·직무별 활용 시나리오 맵 (Scenario Map by Function)

- **쓰는 상황**: "그래서 우리 직원이 실제로 뭘 하게 되나"에 답하는 장표. 교육 설계·파일럿 대상 선정·시나리오 우선순위 논의의 근거로 쓴다. Microsoft Copilot Scenario Library의 부서별 구성 방식을 따른다.
- **도식 구조**: 매트릭스 표. 행 = 부서·직무(영업, 마케팅, 재무, HR, IT, 운영, 고객서비스 등 고객 조직에 맞게 교체), 열 = 업무 활동 4개(회의·소통 / 문서 작성 / 데이터 분석 / 지식 검색). 셀마다 시나리오명 1개 + 사용 앱(Word·Teams·Excel·Copilot Chat 등) 작은 표기. 우선순위 상위 시나리오는 셀 배경 강조 + 별표(★)와 범례. 맵 아래에 시나리오 상세로 넘어가는 화살표와 "상세는 시나리오별 장표 참조" 캡션.
- **장표 구성**: 액션 타이틀 예시 — "교육 단위를 'Copilot 기능'이 아니라 '내 업무 시나리오'로 잡아야 사용률이 붙는다". 본문 요소: 셀별 시나리오명, 사용 앱, 기대 효과 유형(시간 절감/품질 향상/속도 개선 중 택1), 측정 KPI 1개. 수치 표기법: 효과는 유형으로만 표기하고 셀 안에 절감률 같은 수치를 넣지 않는다.
- **주의점**: Scenario Library의 예시 시나리오를 고객의 실제 업무인 것처럼 단정하지 않는다 — 고객 인터뷰·업무 분석으로 교체한다는 전제를 각주로 명시한다. 부서명은 고객 공식 조직명을 쓰고, 없는 부서를 라이브러리 구성 그대로 옮기지 않는다.

## 패턴 4. 라이선스·비용 구성 (License & Cost Structure)

- **쓰는 상황**: 예산 논의 장표. Copilot이 단독 제품이 아니라 기존 Microsoft 365 구성 위에 얹히는 애드온 구조임을 설명하고, 단계별 물량을 합의할 때.
- **도식 구조**: 좌측 적층 블록(하단부터): ① 기본 라이선스(Microsoft 365 E3/E5 등) ② Microsoft 365 Copilot 애드온 ③ 부가 구성(Viva Insights, SharePoint Advanced Management, Copilot Studio 크레딧 등 해당 시). 블록마다 '구성 요소'와 '역할' 2줄. 우측은 단계별 수량 표(파일럿 n명 / 확산 n명 / 전사 n명 — 열: 단계·대상·수량). 가격 열은 만들지 않고 표 하단에 "단가·총액은 별도 산정" 박스를 둔다.
- **장표 구성**: 액션 타이틀 예시 — "Copilot은 기본 라이선스 위에 얹는 구조이므로, 구성과 단계별 물량부터 확정해야 예산이 흔들리지 않는다". 본문 요소: 구성 요소별 역할, 단계별 대상·수량, 포함/미포함 범위. 수치 표기법: 수량은 명 단위 확정값 또는 범위(n~n명)로, 단가·합계는 기재하지 않는다.
- **주의점**: 단가·할인·프로모션을 임의로 적지 않는다(가격 변동·협상 여지가 크다). Copilot 애드온의 전제 라이선스 요건, Copilot Studio 크레딧 구조처럼 바뀔 수 있는 라이선싱 조건은 "제안 시점 Microsoft 공식 라이선싱 페이지 기준 재확인" 각주를 붙인다. 고객이 이미 보유한 라이선스를 확인 없이 '신규 구매 필요'로 쓰지 않는다.

## 패턴 5. 성과측정 체계 (Measurement Framework — 3-Layer)

- **쓰는 상황**: "효과를 어떻게 증명할 것인가"에 답하는 장표. 파일럿 게이트(패턴 2), 사후 결과 보고, 확산 의사결정의 측정 근거로 연결된다.
- **도식 구조**: 3층 적층 박스. 1층 「시스템 지표 — Copilot Dashboard(Microsoft Viva Insights)」: Readiness / Adoption / Impact / Sentiment 4개 영역 박스를 나란히 넣고 각 영역 대표 지표 2개씩. 2층 「인식 지표 — 설문·인터뷰」: 만족도, 체감 시간 변화, 심리적 장벽, Viva Glint·Pulse 연계 표기. 3층 「업무 지표 — 부서 KPI」: 과업 처리시간, 사이클타임, 재작업률 등 고객 지표. 왼쪽 세로 축에 측정 시점 3개(도입 전 베이스라인 → 파일럿 종료 → 확산 후)를 화살표로 연결한다.
- **장표 구성**: 액션 타이틀 예시 — "사용률만으로는 부족하다 — 대시보드·설문·업무지표 3층으로 봐야 효과를 말할 수 있다". 본문 요소: 층별 지표, 수집 도구, 측정 주기, 보고 대상. 수치 표기법: 목표값은 베이스라인 측정 후 확정한다고 명시하고, 장표에는 지표명과 측정 방식만 쓴다.
- **주의점**: Copilot Dashboard의 '절감 시간'은 Microsoft 산정 모델 기반 추정치이므로 실측값처럼 쓰지 않고 "대시보드 추정"임을 병기한다. 베이스라인 없이 사후 수치만으로 효과를 주장하지 않는다. 지표는 부서·그룹 단위 집계가 원칙이며 개인 단위 사용량으로 개인을 평가하는 설계로 쓰지 않는다(최소 그룹 크기 등 프라이버시 원칙 명시).

## 패턴 6. 보안·거버넌스 (Security & Oversharing Governance)

- **쓰는 상황**: IT·보안 부서가 반대하거나 우려를 표할 때, 도입 전 점검 범위를 합의할 때. 경영진 장표보다 보안 실무 검토 회의에서 자주 쓴다.
- **도식 구조**: 좌측 데이터 경계 다이어그램 — 큰 경계 박스(고객 테넌트) 안에 데이터 박스(SharePoint·OneDrive·Teams·메일)와 Copilot 박스를 넣고, Copilot↔데이터 사이에 "기존 권한 범위 내에서만 접근" 화살표. 경계 밖에는 웹·외부 서비스 박스를 분리 배치. 우측 리스크-대응 2열 표 3~4행: 과다 공유(oversharing) → 공유 권한 정리·SharePoint Advanced Management / 민감 정보 노출 → Microsoft Purview 민감도 레이블·DLP / 사용 이력 → Purview 감사 로그·접근 검토.
- **장표 구성**: 액션 타이틀 예시 — "Copilot은 새 권한을 만들지 않는다 — 이미 열려 있던 공유 범위가 그대로 드러나는 것이 핵심 리스크다". 본문 요소: 권한 모델(기존 Microsoft 365 권한 상속), Semantic Index 개념 한 줄, 도입 전 점검 체크리스트(권한 현황 진단, 레이블 적용 범위, 공유 링크 정책). 수치 표기법: 점검 항목 수·대상 사이트 수처럼 범위 수치만 쓰고, 고객 현황 수치는 진단 후 기입란으로 비워 둔다.
- **주의점**: "100% 안전" "유출 불가" 같은 절대 표현 금지. '고객 데이터는 모델 학습에 사용되지 않는다'는 Microsoft 공식 입장을 인용할 때만 쓰고 출처를 붙인다. 고객의 현재 공유·권한 상태를 진단하지 않은 채 특정 대응책이 '필수'라고 단정하지 않는다.

## 패턴 7. 프롬프트 역량 교육 체계 (Prompt Capability Curriculum)

- **쓰는 상황**: 교육 제안의 커리큘럼 장표. 'Copilot 사용법 특강 1회'로 끝내지 않고 단계형 역량 체계로 제안해 교육 범위와 단가를 정당화할 때.
- **도식 구조**: 3단 계단(step) 도형, 왼쪽 아래에서 오른쪽 위로 상승. 1단 「기초 — 전 직원」: Copilot 기본 동작, 프롬프트 구성 요소(목표·맥락·자료·형식), 보안 수칙. 2단 「실무 — 부서별」: 패턴 3 시나리오 기반 실습, 부서별 프롬프트 라이브러리 구축. 3단 「심화 — 챔피언·파워유저」: 고급 패턴, 에이전트 활용, 동료 코칭법. 각 단마다 아래에 대상·형식·시간·산출물 4개 작은 박스를 붙인다.
- **장표 구성**: 액션 타이틀 예시 — "프롬프트 교육은 1회 특강이 아니라 기초-실무-심화 단계로 설계해야 현업 사용으로 이어진다". 본문 요소: 단계별 학습 목표, 대상, 진행 형식(집합/온라인/실습 비중), 산출물(프롬프트 라이브러리, 업무 적용 과제). 수치 표기법: 단계별 시간·회차는 '예시'로 표기하고 고객 일정 협의 후 확정.
- **주의점**: '프롬프트 엔지니어링 전문가 양성' 같은 과장 표현을 쓰지 않는다 — 목표는 현업 과업 적용이다. 기초 단계에 보안·윤리 수칙을 반드시 포함한다(패턴 10과 연결). Microsoft 공식 학습 자원(Copilot Success Kit의 enablement 자료, Viva Learning 경로 등)과 병행 가능하다고 쓸 때는 실제 고객 테넌트에서 쓸 수 있는지 확인 후 기재한다.

## 패턴 8. 챔피언 프로그램 운영 구조 (Champions Program)

- **쓰는 상황**: 확산 단계의 변화관리 실행 장표. 교육 이후 사용이 꺼지는 구간을 메우는 사내 전파 체계로 제안할 때, 패턴 1 로드맵의 공통 기반과 연결된다.
- **도식 구조**: 중심 원(Circle) 「프로그램 운영 주체(HRD/변화관리 담당)」 + 방사형으로 연결된 위성 박스 4~6개 「부서별 챔피언」. 하단에 챔피언 역할 4박스 가로 배열: 사용 전파·팁 공유 / 피드백 수집 / 동료 사용 지원 / 성공 사례 발굴. 오른쪽에 운영 리듬 표(선발 → 교육 → 정기 모임 → 사례 공유회) 4행.
- **장표 구성**: 액션 타이틀 예시 — "챔피언은 자발적 모임이 아니라 역할과 운영 리듬을 설계한 공식 전파 네트워크다". 본문 요소: 챔피언 선발 기준, 역할 정의, 운영 리듬(모임 주기·채널), 본 프로그램의 지원 범위(심화 교육, 자료, 운영 코칭). 수치 표기법: 챔피언 규모는 '대상 인원의 약 5~10% 수준(예시)'처럼 범위로만 쓴다.
- **주의점**: 챔피언에게 본업 외 무제한 지원 업무를 지우는 설계로 쓰지 않는다 — 역할 범위와 소요 시간을 명시한다. 인센티브·인사 반영 같은 고객 내부 제도를 확정된 것처럼 약속하지 않는다. '얼리어답터면 된다'는 식으로 선발 기준을 비우지 않는다(부서 내 신뢰도·전파력이 기준).

## 패턴 9. 일하는 방식 변화 (New Ways of Working)

- **쓰는 상황**: 도구 도입을 넘어 업무 프로세스 재설계로 제안의 격을 올릴 때. 경영진 보고에서 "왜 변화관리가 필요한가"의 논거 장표.
- **도식 구조**: As-Is / To-Be 2열 대조. 열마다 업무 프로세스 4~5단계 박스(예: 회의 — 준비→진행→결정→후속 실행)를 가로로 놓고, To-Be 열의 각 단계에 Copilot 개입 지점을 점선 박스로 겹쳐 표시한다. 두 열 사이에 변화 화살표, 하단에 행동 변화 지표 띠(회의 후속 처리 시간, 초안 작성 리드타임 등 측정 가능한 항목 3개).
- **장표 구성**: 액션 타이틀 예시 — "바뀌는 것은 도구 사용법이 아니라 회의·문서·보고의 일하는 방식 자체다". 본문 요소: 프로세스별 현재 방식, 변화 후 방식, 필요한 행동 변화(리더의 회의 운영 방식 등), 측정 지표. 수치 표기법: 외부 조사 수치를 인용할 경우 Microsoft Work Trend Index 등 출처명과 조사 연도를 반드시 병기하고, 고객 효과는 '측정 지표'로만 제시한다.
- **주의점**: "업무 시간 ○% 절감"을 고객에게 일어날 일처럼 단정하지 않는다 — 자사 측정으로 검증한다는 구조로 쓴다. As-Is를 과도하게 부정적으로 그려 고객 현업을 폄하하지 않는다. 프로세스 예시는 고객의 실제 업무 흐름으로 교체한다.

## 패턴 10. AI 거버넌스·윤리 원칙 (AI Governance & Responsible AI)

- **쓰는 상황**: 고객사에 AI 사용 정책·가이드라인이 없거나, 임직원 불안(일자리·정보 유출)을 다뤄야 할 때. 보안 장표(패턴 6)가 기술 통제라면 이 패턴은 원칙과 의사결정 체계다.
- **도식 구조**: 상단 2행 3열 원칙 박스 6개 — Microsoft Responsible AI 6원칙을 공식 명칭으로: 공정성(Fairness) / 신뢰성·안전(Reliability & Safety) / 프라이버시·보안(Privacy & Security) / 포용성(Inclusiveness) / 투명성(Transparency) / 책임성(Accountability). 하단 운영 체계 4박스 가로 배열: 의사결정 기구(AI 협의체) / 사용 정책·가이드라인 / 임직원 교육 / 모니터링·개선. 원칙과 운영 체계 사이에 "원칙 → 실행" 화살표.
- **장표 구성**: 액션 타이틀 예시 — "원칙 선언에서 멈추지 않고 의사결정 기구와 운영 절차까지 내려와야 거버넌스가 된다". 본문 요소: 6원칙 한 줄 설명, 고객사 적용 범위(허용/주의/금지 사용 구분 예시), 운영 체계별 담당. 수치 표기법: 수치보다 구분 체계(허용-주의-금지 3등급) 표기가 중심.
- **주의점**: 6원칙의 공식 명칭을 바꾸거나 줄이지 않는다. 고객사 내부 규정·법무 검토가 우선한다는 전제를 명시하고, 이 장표를 법적 자문처럼 단정적으로 쓰지 않는다. 허용/금지 사용 예시는 고객 업종 규제(금융·공공 등)에 따라 달라지므로 예시임을 밝힌다.

## 패턴 11. 도입 후 고도화 — 에이전트 확장 (Extend with Agents — Copilot Studio)

- **쓰는 상황**: 패턴 1 로드맵의 마지막 단계(Extend & Optimize)를 구체화하는 장표. 초기 도입 제안에 중장기 비전을 붙이거나, 고도화 2차 사업을 제안할 때.
- **도식 구조**: 4단 상승 계단. 1단 「Copilot 활용 정착」: 전 직원 기본 활용·시나리오 확장. 2단 「부서 에이전트」: Copilot Studio 선언형 에이전트로 부서 반복 질의·문서 검색 자동화. 3단 「업무 시스템 연결」: 커넥터로 사내 시스템 데이터 연결, 승인·검토 절차 포함. 4단 「프로세스 자동화」: 다단계 업무 흐름 자동화, 사람 검토 지점 명시. 각 단 오른쪽에 거버넌스 게이트 박스(승인 주체·모니터링 방법)를 짝지어 배치한다.
- **장표 구성**: 액션 타이틀 예시 — "고도화의 방향은 '더 많이 쓰기'가 아니라 반복 업무를 에이전트에 단계적으로 맡기는 것이다". 본문 요소: 단계별 대상 업무, 필요 준비(데이터·권한 정비 — 패턴 6 연결), 운영 주체(CoE 또는 담당 조직), 측정 지표(에이전트 사용량·처리 건수). 수치 표기법: 단계 진입 조건을 사용률·안정화 기간 같은 조건값으로 쓰고, 자동화 효과 수치는 기재하지 않는다.
- **주의점**: '완전 자율' '사람 불필요' 같은 표현 금지 — 단계마다 사람 검토·승인 지점을 명시한다. Copilot Studio 이용에는 별도 라이선스·크레딧 구조가 있으므로 비용은 패턴 4 원칙대로 별도 산정으로 둔다. 에이전트 확산 속도는 고객의 데이터·권한 준비도가 결정하므로, 준비도 진단 없이 일정을 약속하지 않는다.
