## 기본 작업 순서 (모든 제안서 공통)

1. **원고부터 표로 확정** — 장표 번호 · 장표 역할 · 헤드메시지(결론 1문장) · 보조설명(1줄) · 논리 구조 · 레이아웃 · 필요한 이미지.
   디자인 지시는 이 단계에서 하지 않는다. 표는 사용자에게 먼저 보여 주고 확정받는다.
2. **헤드메시지 검사** — 헤드메시지만 이어 읽어도 제안의 결론과 근거가 통해야 한다(`checklist.md` 1번).
3. **디자인 규칙 고정** — 표준 템플릿이 있으면 그 템플릿 규칙을 따른다(표준 폰트 Noto Sans KR).
   템플릿 없이 새로 만들면 전역 규칙 `rules/ppt.md`(Freesentation 7 Bold, `bold:true` 금지)를 따른다.
   게시물 속 프리텐다드·Paperlogy 같은 폰트는 예시일 뿐, 우리 규칙이 우선이다.
4. **샘플 2장 먼저** — 표지 + 본문 1장(보통 과정 개요 또는 해결 방향)만 만들어 확인받고, 고칠 점은 개별 장표가 아니라
   «규칙»에 반영한 뒤 나머지를 한 번에 만든다.
5. **제작** — 템플릿 기반 교육 제안서는 jj-proposal-full / auto_proposal 흐름으로 만든다.
6. **검수** — `checklist.md` 전 항목. 납품은 편집 가능한 .pptx(원본) + PDF(열람), 필요하면 HTML 열람본.

## 레이아웃·컴포넌트 이름 자동 적용 (ai-layout-names 연동)

사용자가 배치나 부품 이름을 지정하지 않아도, 덱을 만들 때 `ai-layout-names` 스킬의 이름을 Claude가 스스로 골라 적용한다. 사용자가 이름을 직접 말하면 그 지시가 우선이다.

- **장표 역할 → 레이아웃 자동 선택**: 표지=히어로 / 특징·기능 소개=벤토 그리드 / 전후·좌우 대조=스플릿 / 사례·스토리=매거진 / 항목 나열=카드 그리드 / 전면 이미지=풀블리드 / 한 장 메시지의 시선 흐름=Z 패턴. 사이드바·대시보드는 웹·앱 전용이라 PPT에 억지로 넣지 않는다.
- **화면이 들어가는 장표**: 앱·웹 화면 목업과 그 제작 지시에 컴포넌트 이름(토스트·스낵바·모달·바텀시트·스켈레톤·토글 등)을 정확히 쓴다. 헷갈리는 쌍(토스트 vs 스낵바, 토글 vs 체크박스 등)은 ai-layout-names의 구분 기준을 따른다.
- **원고 표에 이름을 적는다**: 기본 작업 순서 1번의 원고 표 "레이아웃" 칸에 위 이름으로 적어, 사용자가 검토할 때 무엇이 적용됐는지 보이게 한다.

## 자동으로 함께 쓰는 지식 스킬 (사용자가 부르지 않아도 적용)

덱을 만들 때 아래 지식 스킬은 사용자가 이름을 말하지 않아도 Claude가 알아서 골라 적용한다. 사용자가 직접 지정하면 그 지시가 우선이다. 각 스킬의 자동 적용 조건·우선순위는 해당 스킬 파일이 정본이다.

| 스킬 | 언제 자동 적용하나 | 경계 |
|---|---|---|
| `ai-layout-names` | 모든 덱 — 장표 배치 이름, 화면 목업의 부품 이름 | 위 자동 적용 규칙 절 참조 |
| `ai-color-combos` | 표지·이미지·포스터 등 비주얼 자리에서 색 방향이 없을 때 | 브랜드·템플릿 표준 색이 있으면 그게 우선, 이 조합은 안 쓴다 |
| `design-reference-first` | 템플릿 없는 신규 덱·화면의 비주얼 방향을 잡을 때 | 확정 템플릿 작업에는 미적용. 유료 갤러리 기능 금지 |
| `claude-prompt-libraries` | HTML 웹덱·랜딩 섹션을 만들 때 | .pptx 납품본에는 미적용. Motion 유료 칸 금지 |
| `ppt-commands` | 사용자가 /명령어를 부를 때, 또는 단계별 진행이 맞을 때 | 기획 원칙의 정본은 이 스킬(ppt). 명령어는 실행 도구 |

## 핵심 원칙 5가지 (외워 둘 것)

1. **장표 1장 = 메시지 1개.** 상단에 결론형 헤드메시지, 바로 아래 한 줄 보조설명. 제목("추진 배경")이 아니라 주장("현장 리더의 피드백 역량이 성과 격차의 1순위 원인이다")을 쓴다.
2. **결론 먼저(BLUF).** 첫 본문 장표에 제안의 결론·기대효과·투자 규모를 한 장으로.
3. **글 먼저, 디자인 나중.** 내용을 틀에 끼워 맞추면 문장이 잘리고 논리가 비틀린다. 원고 분량에 맞춰 틀을 고른다.
4. **숫자로 말한다.** 기대효과·사례는 STAR 구조와 전후 수치(예: 9명→27명, 3배)로. "만족도 높음" 같은 말 대신 지표.
5. **한 장에 강조색은 한 곳.** 핵심 칸 하나만 포인트 컬러, 나머지는 회색·연한 톤. 같은 도식이 3장 이상 연달아 나오지 않게 바꾼다.
