# Deck Craft — 다이어그램 중심 컨설팅 덱 제작 표준

배경 (2026-11-22 사용자 판정): 기존 파이프라인 산출물은 "박스·선 나열이라 컨설팅 같지 않고 허접하다"는 평가를 받았다. 원인은 세 가지 — ① 색을 추측으로 넣음 ② 장의 주인공이 카드 그리드뿐이라 도식이 없음 ③ 렌더링 검수 없이 납품. 이 스킬은 그 셋을 규칙으로 막는다. **덱 기획의 진입점·원칙은 `ppt` 스킬이 정본이고, 이 스킬은 디자인 시스템과 제작·검수 표준을 담당한다.**

## 절대 규칙 5개

1. **색은 추측하지 않되, 하나로 고정하지도 않는다.** 아래 팔레트 라이브러리에서 주제·고객 업종·청중에 맞는 후보 2~3개를 골라 **표지 샘플에 각각 입혀 보여주고**, 사용자가 눈으로 고른 것으로 전체를 만든다. 사용자가 위임하면 Claude가 골라 진행하되 어떤 팔레트인지 알린다. 브랜드·고객사 지정 색이 있으면 그 값이 최우선.
2. **장마다 다이어그램 1개가 주인공이다.** 본문 장은 아래 카탈로그에서 도식 1개를 골라 장 면적의 절반 이상을 차지하게 한다. 카드·박스는 도식을 보조할 때만 쓴다. 카드 그리드만으로 장을 채우는 것은 금지.
3. **포인트 색은 슬라이드당 1곳만.** 핵심 숫자·핵심 막대·결론 바 중 하나.
4. **렌더링 검수 없이 납품하지 않는다.** 전 장을 이미지로 렌더링해 눈으로 확인한다: 글자 겹침·선 겹침·잘림·넘침이 한 건이라도 있으면 고치고 다시 렌더링한다.
5. **샘플 2장 먼저.** 표지+본문 1장을 먼저 만들어 사용자 확인을 받고 전체를 제작한다.

## 디자인 시스템 — 팔레트 라이브러리 (고르고, 보여주고, 확정)

고정 팔레트는 없다. 아래 8종에서 덱마다 골라 쓴다. 한 덱 안에서는 한 팔레트만 유지하되, **덱이 바뀌면 같은 팔레트 반복을 피한다** (같은 고객의 시리즈 덱은 예외 — 시리즈 정체성이 우선).

**선택 절차:** ① 주제·업종·청중으로 후보 2~3개로 좁힌다 ② 표지 1장에 각 팔레트를 입힌 샘플을 나란히 보여준다 ③ 사용자가 고르면 그 팔레트로 샘플 2장째(본문)까지 확인받고 전체 제작. "알아서 해"면 Claude가 1순위를 골라 진행하고 팔레트 이름을 밝힌다.

**고급스러움은 색보다 먼저 여백·타이포 대비·정렬에서 나온다.** 팔레트를 바꿔도 §타이포·여백 스펙(고정 마진, 헤어라인, 본문 30~40% 비우기, 고스트 숫자)은 그대로 지킨다. 팔레트만 바꿔놓고 여백이 무너지면 다시 허접해진다.

## 제작 팀 — 기획자·디자이너·컨설턴트 3역할

덱 제작은 한 번에 뽑지 않고 세 역할로 나눠 돌린다. `agents/` 폴더의 에이전트 정의를 PC의 `~/.claude/agents/`에 복사해 두면 서브에이전트로 각각 호출할 수 있고, 에이전트 파일이 없는 환경에서는 이 절차대로 역할을 나눠 스스로 수행한다.

1. **기획자 (deck-planner)** — 스토리라인·원고 표(헤드메시지·근거·도식 지정)·수치 출처 확정. 산출물 없이 다음으로 안 넘어간다.
2. **디자이너 (deck-designer)** — 팔레트 선택(라이브러리 + 위 탐색 도구)·도식 설계·HTML 제작. 기획자의 원고 표를 바꾸지 않는다 (내용 변경이 필요하면 기획자에게 반려).
3. **컨설턴트 (deck-consultant)** — 검수 전담. 논리(BLUF·MECE), 수치 출처, 팔레트 규칙(포인트 1곳·대비), 렌더링 전수 검수(겹침·잘림·넘침)를 채점하고, 미달이면 어느 역할로 돌려보낼지 명시해 반려한다. **컨설턴트 통과 없이 납품 금지.**
4. 반려 루프는 최대 3회. 3회에도 안 되면 사용자에게 막힌 지점을 보고한다.

## 타이포·여백 스펙

- 폰트: 한글 Pretendard 단일 패밀리(웨이트로 위계), 영문 키커·숫자는 Inter. 숫자는 tabular. Pretendard는 Windows 기본 폰트가 아니므로 제출은 PDF 병행이 원칙.
- 표지 제목 40~54pt Bold, 행간 1.15, 2줄 이내. 본문 액션 타이틀 24~28pt SemiBold, 완결된 결론 문장, 최대 2줄 (명사구 제목 금지).
- 키커: 영문 대문자 11~12pt, 자간 +0.20em. KPI 숫자 32~44pt Bold, 단위는 작게. 본문 13~15pt, 행간 1.35~1.5, 장당 6줄 내외. 출처·각주 8.5~10pt 우하단 고정.
- 마진 고정: 좌우 0.6in, 상 0.5in, 하 0.4in — 전 장 동일. 12열 그리드에 스냅, 간격은 8의 배수.
- 액션 타이틀 밴드: 키커 → 액션 타이틀 → 0.75pt 헤어라인. 본문 영역의 30~40%는 비운다.
- 모서리 반경 0·그림자 없음이 원칙 (현대식 카드로 갈 경우 반경 8px 이하, 소프트 섀도 1종만). 좌측 정렬 기본, 가운데 정렬은 표지·간지·마무리만.
- 푸터 고정: 좌하단 페이지 번호, 우하단 출처, 기밀 표기.

## 다이어그램 카탈로그 — 장의 주인공 고르기

원고 표에 "도식" 칸을 두고 장마다 하나를 지정한다.

| 도식 | 언제 쓰나 | 대표 장 |
|---|---|---|
| 방사형 허브 | 중심 개념과 구성 요소 3~5개의 관계 | 프레임워크, 사업 구조 |
| 레이더(스파이더) 진단 | 다축 성숙도·역량 진단, 현재 vs 목표 | 진단 결과, 성숙도 평가 |
| 도넛·아크 | 비중·달성률 단일 지표 | 도입률, 점유율 |
| 셰브론 프로세스 | 단계별 절차 3~6단계 | 실행 계획, 온보딩 |
| S곡선·상승 곡선 | 도입 확산, 성장 궤적 | 확산 단계, 성과 추이 |
| 곡선 로드맵 | 시간축 위 마일스톤 (직선 타임라인 대체) | 30·60·90일 계획 |
| 사이클(순환) | 반복 운영 체계 | 운영 모델, 거버넌스 |
| 스펙트럼 화살표 | 선행→후행, 현재→목표의 연속 축 | 지표 체계, 전환 방향 |
| 2x2 매트릭스 | 두 축으로 분류·우선순위 | 과제 우선순위, 포지셔닝 |
| 피라미드 | 위계·구성 비중 | 조직 구조, 비용 구조 |
| 비교 막대 (대비쌍) | 미흡 vs 우수, 전 vs 후 | 효과 검증, 사례 수치 |
| 풀블리드 히어로 | 표지·간지·마무리 | 섹션 전환 |

## 제작 절차

1. **원고 표** — `ppt` 스킬 절차대로 장별 헤드메시지·근거·레이아웃을 짜고, 여기에 **도식 칸**을 추가한다. 수치에는 출처를 붙인다 (가짜 수치 금지).
2. **샘플** — 먼저 표지 1장에 후보 팔레트 2~3개를 입혀 나란히 보여주고 사용자가 고른다. 확정되면 도식이 가장 복잡한 본문 1장을 같은 팔레트로 만들어 타이포·도식 품질까지 확인받는다.
3. **전체 제작** — HTML로 만든다 (SVG로 도식을 직접 그린다). 곡선·방사형·레이더는 SVG 좌표를 계산해서 그릴 것 — 도형 근사치로 때우지 않는다.
4. **전수 검수** — 전 장 렌더링 이미지로 확인: 겹침·잘림·넘침·선 겹침·대비. 문제 장은 고치고 재렌더링. 검수를 통과한 것만 납품한다.
5. **산출** — HTML 원본 + PDF. PPTX가 필요하면 아래 경로 규칙을 따른다.

## PPTX가 필요할 때 (솔직한 경로)

- 파워포인트 앱 기능으로는 이 도식들이 전부 가능하지만, 코드 자동 생성(PPTX)에서는 곡선·방사형의 좌표 계산과 검수 순환이 무거워 품질 수렴이 느리다. 이 사실을 사용자에게 먼저 말한다.
- 권장: **하이브리드** — 도식 중심 장은 HTML 렌더링 이미지로 PPTX에 넣고(모양 유지, 그 장만 편집 불가), 텍스트 위주 장은 네이티브 도형으로 편집 가능하게 만든다.
- 전면 네이티브 PPTX를 원하면 제작 시간이 몇 배가 들고 곡선 도식은 도형 근사치로 바뀔 수 있음을 알리고 진행한다.
- 고객사 확정 템플릿이 있는 납품본은 `jj-proposal-full`이 정본 — 이 스킬의 팔레트·도식 규칙을 그 템플릿 위에 얹는다.

## 하지 않는 것

- 레퍼런스·팔레트 확정 없이 "예쁘게"만으로 신규 스타일을 지어내지 않는다. 방향이 없으면 `design-reference-first` 절차로 레퍼런스부터 고른다.
- 미리캔버스 템플릿을 그대로 복제하지 않는다 — 구조 문법(흰 배경+네이비, 키커→대제목→하단 바)만 참고하고 색은 위 팔레트로 낮춰 프리미엄으로 만든다.
- 그라디언트·그림자·둥근 모서리로 "디자인한 티"를 내지 않는다.
