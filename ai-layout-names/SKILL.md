# AI에게 레이아웃 이름으로 시키기

검증: 2026-11-11. 릴스(@uxwoodytips, 2026-11-10)와 크리에이터 이력 대조 확인. 만든 사람 우디(김성연, [우디디자인랩] 대표)는 11년 현업 디자이너·PO로, 저서 『사용자를 사로잡는 UX/UI 실전 가이드』·『사실은 이것도 디자인입니다』·『GEN Z 인문학』 3권, 제10회 브런치북 출판 프로젝트 대상, EBS 비즈니스 리뷰 강연. 국회도서관에 저서 소장 기록 있음. 9개 레이아웃 이름은 전부 업계 표준 용어라 별도 검증이 필요 없는 상식 수준이다.

## 기본 모드 — 자동 적용 (사용자가 외워서 지정하지 않는다)

이 스킬의 이름들은 사용자가 외워서 말하라고 있는 게 아니다. 화면·슬라이드·덱을 만드는 작업에서 **Claude가 이 이름들을 스스로 골라 적재적소에 적용**하는 게 기본이다.

- 사용자가 "덱 만들어줘" "화면 만들어줘"만 말해도, 구역·장표 역할에 맞는 레이아웃 이름을 골라 배치하고, 화면 속 부품은 컴포넌트 이름 기준으로 정확히 만든다.
- 사용자가 이름을 직접 지정하면 그 지시가 우선한다.
- PPT 덱에서는 `ppt` 스킬이 이 스킬을 연동해 자동 적용한다. 장표 역할 → 레이아웃 매핑은 ppt 스킬의 자동 적용 규칙을 따른다.

## 원리 — "깔끔하게"는 매번 다른 화면을 만든다

"AI한테 깔끔하게 배치해 줘"라고 하면 기준이 없어서 매번 다른 화면이 나온다. 화면 배치에도 이름이 있다. 이름을 말하면 AI도, 개발자도 훨씬 빨리 알아듣는다. 첫마디가 달라지는 게 핵심이다.

## 9개 레이아웃 이름

1. **히어로 Hero section** — 맨 위 대형 첫 화면. 한 문장 메시지 + 핵심 버튼 + 대표 이미지·영상. 랜딩·홍보 페이지의 첫인상.
2. **벤토 그리드 Bento grid** — 크기가 다른 카드를 바둑판처럼 채우는 격자. 기능·특징을 한눈에 보여줄 때. 도시락통 칸막이 같은 배열.
3. **스플릿 Split screen** — 화면을 둘로 나눠 한쪽은 글, 한쪽은 이미지. 두 가지를 나란히 비교·대조할 때.
4. **카드 그리드 Card grid** — 같은 크기 카드를 반복해 나열. 상품·게시글·목록처럼 균일한 항목을 보여줄 때.
5. **사이드바 레이아웃 Sidebar layout** — 옆에 고정 메뉴 + 본문. 대시보드·관리자·문서형 서비스.
6. **매거진 Magazine layout** — 잡지처럼 큰 이미지와 글을 엇갈리게 배치. 에디토리얼·콘텐츠·스토리텔링 페이지.
7. **대시보드 Dashboard** — 숫자·차트·상태를 한 화면에 모아 보여주는 배치. 현황 파악·관리 화면.
8. **Z 패턴 Z-pattern** — 시선이 Z자로 흐르게 배치한다. 왼쪽 위 → 오른쪽 위 → 왼쪽 아래 → 오른쪽 아래. 단순한 랜딩·마케팅 페이지.
9. **풀블리드 Full bleed** — 여백 없이 화면 끝까지 이미지를 채우는 배치. 몰입감 있는 비주얼·사진 중심 페이지.

## 쓰는 법 — 구역별로 이름을 붙여 말한다

레이아웃은 한 화면에 하나만 쓰는 게 아니다. 구역마다 이름을 붙여 조합한다.

```
// 붙여넣기

맨 위는 히어로로 크게, 아래는 카드 그리드 3열로 만들어 줘
```

```
// 붙여넣기

맨 위 풀블리드 이미지, 그 아래 스플릿으로 기능 설명, 마지막은 카드 그리드로 후기 보여줘
```

```
// 붙여넣기

왼쪽 사이드바 레이아웃에 대시보드를 넣어줘. 상단은 숫자 카드 4개, 아래는 차트 2개
```

팁: "예쁘게 해줘" "깔끔하게 해줘" 같은 말은 빼고, 구역 + 레이아웃 이름 + 개수(3열, 2단)만 적으면 된다. 색·서체는 따로 말한다.

## PPT·EDM에 가져다 쓰기

9개 이름이 웹·앱 화면용이라 PPT나 메일에 그대로는 안 맞는다. 통하는 것만 가져다 쓰면 된다. PPT·EDM은 한 화면이 아니라 한 장·한 메일 단위라, 레이아웃 이름을 "슬라이드 종류"나 "메일 구역"으로 바꿔 말하면 된다.

| 레이아웃 | PPT | EDM(메일) |
| --- | --- | --- |
| 히어로 | 표지 슬라이드(한 문장 + 핵심 이미지) | 상단 배너 |
| 벤토 그리드 | 특징·기능 소개 슬라이드 | 메일 폭이 좁아 제한적 |
| 스플릿 | 좌우 대조 슬라이드(전후 비교 등) | 메일 폭이 좁아 제한적 |
| 카드 그리드 | 3단 카드 슬라이드 | 상품·콘텐츠 나열 |
| 사이드바 | 안 맞음(웹·앱 전용) | 안 맞음 |
| 매거진 | 사례·스토리 슬라이드 | 에디토리얼형 메일 |
| 대시보드 | 안 맞음(현황 보고 슬라이드는 차트 묶음으로 따로 짠다) | 안 맞음 |
| Z 패턴 | 시선 흐름 — 한 장의 메시지 슬라이드 | 시선 흐름 — CTA까지 이어지는 메일 |
| 풀블리드 | 전면 이미지 슬라이드 | 전면 이미지 배너 |

```
// 붙여넣기

표지는 히어로로 크게, 특징 소개는 벤토 그리드로, 사례는 매거진으로 만들어 줘
```

## 컴포넌트 편 — 부품 이름으로 시키기 (2026-11-22 추가)

레이아웃이 "화면 배치"라면 컴포넌트는 그 안의 "부품"이다. 출처는 같은 크리에이터의 후속 릴스(2026-11-21, "AI한테 시킬 때 쓰는 UI 이름 100개")와 공개 게시물·무료 미니 사전 소개 페이지에 나온 이름들이다. 전체 사전(210개 이름)은 유료 전자책(래피드 14,900원)이라 사지 않았고, 아래는 공개 범위 + 업계 표준 용어만 정리했다. 미니 사전(무료, 90개)은 이메일로 링크를 받아 여는 웹 사전이라 이메일 등록은 하지 않는다.

### 알림·피드백

- **토스트 Toast** — 잠깐 떴다 사라지는 짧은 알림. 버튼이 없다. 예: "저장됐어요"
- **스낵바 Snackbar** — 토스트와 닮았지만 **실행취소 같은 액션 버튼**이 붙는다. 예: 삭제 후 "되돌리기"
- **모달 Modal** — 화면 가운데 뜨고, 닫기 전까지 뒤 화면을 못 만지는 창
- **얼럿 Alert** — 확인·취소처럼 결정을 요구하는 작은 모달
- **바텀시트 Bottom sheet** — 아래에서 쓱 올라오는 창. 모바일에서 확인·선택에 많이 쓴다
- **팝오버 Popover** — 누른 자리 옆에 붙어 뜨는 작은 말풍선 창
- **툴팁 Tooltip** — 아이콘에 갖다 대면(또는 누르면) 나오는 짧은 설명
- **배지 Badge** — 아이콘·글자 옆의 작은 숫자·점 표시. 예: 알림 3
- **배너 Banner** — 화면 위쪽에 길게 붙는 공지 띠

### 로딩

- **스켈레톤 Skeleton** — 내용이 오기 전 깜빡이는 회색 박스 자리표시
- **스피너 Spinner** — 가운데 동그랗게 도는 로딩 표시
- **프로그레스 바 Progress bar** — 진행률을 보여주는 막대

### 입력·폼

- **토글 Toggle** — 켜기·끄기 스위치. **누르는 즉시 적용**된다
- **체크박스 Checkbox** — 여러 개 동시 선택. 고르고 **제출해야 적용**된다
- **라디오 버튼 Radio button** — 여러 개 중 **하나만** 선택
- **드롭다운 Dropdown** — 누르면 목록이 펼쳐지는 선택 칸
- **텍스트 필드 Text field** — 글자를 입력하는 칸
- **슬라이더 Slider** — 손잡이를 밀어 값을 조절. 예: 밝기, 가격 범위
- **스테퍼 Stepper** — −/+ 버튼으로 숫자를 올리고 내리는 칸
- **칩 Chip** — 동그란 알약 모양의 선택·표시 꼬리표. 예: 필터 태그
- **데이트 피커 Date picker** — 달력에서 날짜를 고르는 창

### 구조·이동

- **탭바 Tab bar** — 앱 하단의 큰 메뉴 줄
- **탭 Tabs** — 화면 안에서 내용을 갈아끼우는 작은 메뉴
- **아코디언 Accordion** — 눌러서 접고 펴는 목록
- **캐러셀 Carousel** — 옆으로 넘기는 이미지·카드 줄
- **드로어 Drawer** — 옆에서 밀려 나오는 메뉴 서랍
- **페이지네이션 Pagination** — 목록 아래 페이지 번호
- **브레드크럼 Breadcrumb** — 위에 표시되는 현재 위치 경로 (홈 > 카테고리 > 상품)

### 검색 화면 9가지 (크리에이터 공개 게시물)

서치바 Search bar · 자동완성 Autocomplete · 최근 검색어 Recent searches · 인기 검색어 Trending · 필터 Filter · 정렬 Sort · 하이라이트 Highlight · 결과 없음 No results · 스코프 탭 Scope tabs

### 헷갈리는 쌍만 구분하면 반은 간다

- 토스트 vs 스낵바: 버튼이 있으면 스낵바, 없으면 토스트
- 토글 vs 체크박스: 즉시 적용이면 토글, 제출해야 적용이면 체크박스
- 라디오 vs 체크박스: 하나만 고르면 라디오, 여러 개면 체크박스
- 모달 vs 바텀시트: 가운데서 뜨면 모달, 아래에서 올라오면 바텀시트

### 쓰는 법

```
// 붙여넣기

삭제하면 스낵바로 되돌리기 버튼을 보여줘. 로딩 중에는 스켈레톤으로 보여줘
```

```
// 붙여넣기

설정 화면에 토글 3개랑 드롭다운 1개를 넣어줘. 확인 창은 바텀시트로 올려줘
```

## PPT 제작에 가져다 쓰기

컴포넌트 이름은 화면(슬라이드) 안에 앱·웹 화면이 들어갈 때 통한다.

- **앱·서비스 소개 슬라이드**: 화면 목업을 만들거나 AI로 화면 이미지를 뽑을 때 "휴대폰 화면에 토스트 알림이 뜬 모습", "바텀시트로 결제 창이 올라온 화면"처럼 부품 이름으로 지시하면 원하는 화면이 나온다
- **UX·사용법 교육 자료**: 조작 단계 설명에서 이름이 정확하면 교육생이 실제 화면에서 같은 부품을 바로 찾는다
- **협업 커뮤니케이션**: 개발자·디자이너와 슬라이드를 놓고 얘기할 때 이름이 통하면 수정 요청이 빨라진다
- 반대로 글·도식 중심의 컨설팅 슬라이드에서는 컴포넌트보다 위쪽의 **레이아웃 이름**(히어로=표지, 벤토=특징 소개)이 직접 통한다. 두 편을 나눠 쓴다
