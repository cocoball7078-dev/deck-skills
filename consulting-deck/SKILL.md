# consulting-deck

> **덱 시스템 위치 (2026-10-22 정리)**: 참조 지식층. 덱을 직접 만들지 않고 사고 체계를 공급한다. 기획은 `ppt`, 제작은 `consulting-slide-deck`·`mbb-slides`가 맡는다. 전체 지도: `ppt/references/deck-map.md`.

전략 컨설팅식 PPT 덱(제안서·경영 보고·IR)을 만들 때 적용하는 **지식 스킬**.
MBB 장표 제작의 사고 체계와 AI 시대의 역할 분담을 담는다.
장표 스타일·제작 절차는 `mbb-slides`, `consulting-slide-deck` 스킬과 함께 적용한다.

## 핵심 명제 — AI가 잘하는 것 vs 사람이 해야 하는 것

AI가 PPT를 만들어주는 시대에도 컨설팅 덱의 품질은 사람이 결정한다.

| AI가 잘하는 것 | 사람이 해야 하는 것 |
|---|---|
| 디자인 시안·레이아웃 초안 | 메시지 결정 (무엇을 보여줄지) |
| 리서치 자료 수집·정리 | 스토리라인·구조 설계 |
| 로직트리·목차 초안 | 전략적 판단, 가설 설정 |
| 문장 다듬기, 표·그래프 초안 | 숫자·근거의 타당성 검수 |

원칙: **무엇을 만들지보다 무엇을 보여줄지를 아는 것**이 핵심 역량이다. AI 산출물은 초안으로만 쓰고, 구조와 메시지는 사람이 확정한 뒤에야 덱에 반영한다.

## 장표 제작 6단계

1. **기본 틀 잡기** — 프레임워크와 장표의 기본 구조 이해
2. **스토리라인** — 슬라이드보다 설득 구조를 먼저 세운다
3. **전략 패턴 선택** — 내용에 맞는 패턴을 고른다
4. **디자인** — 패턴에 맞춰 시각화
5. **AI 활용** — 초안·정리 작업 가속
6. **검수** — 메시지 일관성, 근거, 오탈자 최종 점검

## 지식 체계

### 1. 목표 세팅
- 장표를 만들기 전에 "이 덱이 만들 변화"를 한 문장으로 정한다 (의사결정, 투자 유치, 승인 등)
- 가치 있는 장표(소위 '1000억짜리 장표')는 정보량이 아니라 의사결정을 움직이는지로 판단한다

### 2. 스토리라인
- 설득 가능한 스토리라인이 먼저, 슬라이드는 그 다음
- 상황별 스토리라인이 다르다: IR / 투자 제안서(IM) / 신사업 / 벤치마킹
- 스토리라인에서 슬라이드별 **헤드 메시지**를 뽑고, 헤드 메시지 순서만 읽어도 결론이 통해야 한다

### 3. 전략 방법론 3종
- **구조적 접근** — MECE 분해, 로직트리로 문제를 구조화
- **다이나믹 어프로치** — 시간·변화를 축으로 전개
- **마켓 변화** — 시장 변화의 동인과 파급으로 논증

### 4. 슬라이드 패턴 라이브러리
- 7대 상위 개념 패턴
- Value Chain (전략 슬라이드의 핵심)
- 분석 슬라이드 (데이터 → 시사점)
- Graph 표현 (Landscape 비교, Growth 곡선)
- Sales Deck 패턴, Two-box 논리, 시간의 흐름 표현 등 총 12개 패턴군
- 규칙: 슬라이드마다 패턴을 먼저 고르고 내용을 채운다

### 5. 흔한 실수와 잘된 장표
- 초년생 실수 패턴: 정보 나열, 결론 없는 제목, 장식 과다, 근거 없는 주장
- 잘된 장표의 조건: 제목이 결론이다(액션 타이틀), 한 장에 한 메시지, 근거가 보인다, 군더더기가 없다

### 6. AI 활용 기법과 한계
- 활용: 리서치 자료 정리, 로직트리 초안, 스토리라인 초안, 프롬프트 체인(CoT)으로 분석 심화
- 한계: 자동 생성 덱은 구조·판단이 비어 있기 쉽다. 수치·사례는 반드시 원본 대조
- 디자인 기법(몰핑 등 전환 효과)은 메시지 보조 수단으로만

### 7. 실무 노하우
- MECE는 분류가 아니라 누락·중복 점검 도구로 쓴다
- What-if 질문으로 가설을 흔들어 보고 버티는 논리만 남긴다
- 데코레이션과 임팩트 있는 표현을 구분한다 — 장식은 빼고, 강조는 메시지에만
- 팀 작업: 스토리라인을 먼저 합의하면 밤샘 없이 분업이 된다

## 제안서 적용 규칙

1. 덱 제작 전 스토리라인(헤드 메시지 목록)부터 확정한다
2. 각 슬라이드에 패턴을 먼저 배정한다
3. AI 초안은 구조·메시지 검수를 거친 뒤에만 반영한다
4. 완성 후 헤드 메시지만 이어 읽어 결론이 통하는지 확인한다
